## 二、引擎侧分段计时（02:00–02:10，已撤回插桩）

给 `librime-next` 临时加了 `engine/prof.rs`（`WEASEL_PROFILE=1` 开关），在
`process_key → compose → calculate_segmentation / translate_segments / apply_filters`
以及 `table_translator::query`、`make_sentence` 内部打时间戳。release 下喂
`tianqibucuo`（自然码双拼，11 键）实测：

```
processors          0.03–0.17 ms
notify_update       ~0 ms
segmentation        0.01–0.03 ms
menu.prepare        0–0.03 ms
filters             0.08–0.21 ms
translate_segments  0.36–32.4 ms   ← 唯一大头
apply_commit        ~0 ms
```

逐键（ms）：`0.90 / 1.31 / 1.88 / 0.89 / 12.83 / 1.99 / 32.43 / 0.36 / 0.53 / 0.59 / 8.51`

二级下钻：词级查表（`collect_user` + `dict_lookup`）是 µs 级，成本全在
`make_sentence` —— 它是**三重循环**：

```
for start_pos in 0..n            // n = 输入长度
  if !vertices.contains(start_pos) continue
  ① 用户词典：for len in 1..=n  → user_dict.lookup_words(...)   // 每次一次 leveldb get
  ② 编码器  ：for len in 1..=n  → encoder.lookup_phrases(...)
  ③ 词表    ：prism.common_prefix_search(...) 逐条 lookup_words
```

输入越长越慢（O(n²) 量级的查库次数），这与"长句后半段每键 25ms"完全吻合。

> `gear/translation.rs` 新增中，02:30 仍在改 `runtime.rs`），
> 为避免互相踩踏，**已把插桩全部 `git checkout` 撤销**，`librime-next` 恢复干净。
> 上面的数据留给甲路复用。

### 给甲路的建议（未实施，仅提议）

`make_sentence` 里 ①③ 的 `lookup_words(key)` 只取决于 `key` 本身，
与 `start_pos` 无关 —— 而打字过程中**同一批 key 会被逐键反复查**
（`t` → `ti` → `tia` → `tian` …）。加一层按 `key` 的 LRU 记忆化缓存
（用户词典写入时失效）可以砍掉绝大部分重复查库，改动面只在
`table_translator.rs` 内部，不动任何接口。

## 三、宿主侧已落地的改动

### 3.1 乙-1 端到端按键延迟采样（新增）

* `Tip/src/key_latency.rs`（新文件）
  * 量两段：`scoped(budget)` = RPC 等待时长；`probe()` = 整段 TSF 回调时长
    （含 TSF 状态查询 + RPC + 应用结果）。后者才是"应用 UI 线程被占住多久"的完整口径。
  * 开关：放一个空文件 `%APPDATA%\Rime-Next\key-latency.on`（或环境变量
    `WEASEL_KEY_LATENCY=1`）。未开启时只有一次原子读，零开销。
  * 产出：`%LOCALAPPDATA%\Rime-Next\Logs\key-latency.csv`
    列 `at_ms,wait_us,budget_ms,outcome,eaten`，`outcome ∈ ok|timeout|disconnect|total`
  * 攒够 256 条才落一次盘；开关文件每 2 秒才 stat 一次，不做每键系统调用。
* `Tip/src/rpc_worker.rs` `process_key_event` 插桩；`stop()` 里 `flush_pending()`
* `Tip/src/service/key_event.rs` `forward_key_event` 外层包一层 `probe()`
* `Engine/src/key_timing.rs`（新文件）+ `Engine/src/engine.rs`
  * 记 `Session::process_key` 的耗时 → `engine-key-latency.csv`
  * 与 Tip 侧一对减，就能分出 RPC 的份额

### 3.2 主题：每键不再打文件系统（修复）

* `theme/src/config.rs`
  * 新增 `stamp_cached()`：TTL 750ms 的缓存，取代渲染路径上每次的
    `dirs() + 6× metadata()`。换皮肤最迟 0.75 秒生效，日常打字零磁盘访问。
  * 新增 `refresh_stamp_cache()`：真的读过/重载过配置后立刻对齐时间戳，
    避免"刚重载完又被判成已变"。
* `theme/src/mod.rs`
  * `Window::render` 改用 `config::stamp_cached()`
  * `App` 增加 `source` 字段；`reload()` 里的 `diagnostics::record("主题配置: …")`
    改成**只在来源真的变了才写一行** —— 原来无条件写，`theme.log` 因此长到
    25.2 万行 / 72 MB（每次 `record()` open+append+close 实测 0.386 ms）。

### 3.3 Tip 单测修复（既有问题）

`git HEAD` 上 `Tip` 的 3 个测试是**坏的**（未提交的改动把 `CONNECT_KEY_TIMEOUT`
从 500ms 提到 1200ms、`BUSY_KEY_TIMEOUT` 1000ms，测试还按旧的 700ms/1s 写）：

* `key_timeout_invalidates_connection_before_english_fallback`
