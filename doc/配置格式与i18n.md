# 配置格式 与 i18n（两条设计线的记录）

> 2026-10-23。两条线是连着的：**配置能不能用中文** 与 **界面要不要多语言**，决定了配置键该长什么样。
> 结论先写：**配置键固定中文/英文一套（不做 i18n），i18n 只做在界面层。**

## 一、配置格式现状

| 文件 | 格式 | 谁读 |
|---|---|---|
| 出厂 `Rime-Next\weasel.toml` | **TOML** | 我们的 Rust |
| 用户补丁 `%APPDATA%\Rime-Next\weasel.yaml` | **YAML** | 我们的 Rust（`style::parse_file` 只认 YAML） |
| `schema\schema.toml`（勾选清单 + active） | TOML | 我们的 Rust |
| `parser\shuangpin\*.parser.yaml`（双拼键位） | YAML | `shuangpin-schema.exe` |
| `theme\*.theme.toml`、`sound\sound.toml` | TOML | 我们的 Rust |
| `*.schema.yaml` / `*.dict.yaml` / `symbols.yaml` | **YAML** | **librime**（改不得） |

分工规则出处：`artifact/fix-rime-filenames.py:8-9` ——「我们的配置 → TOML，rime 的数据 → YAML」。

### 要不要统一成 YAML

| | 统一 | 保持现状 |
|---|---|---|
| 好处 | 一种格式、一套解析器；`weasel.toml`/`weasel.yaml` 不再两份 | 不迁移；TOML 对"带注释的清单"更友好 |
| 代价 | 要迁移（已有先例 `migrate_legacy_user_config`） | 永远要解释"哪份是出厂、哪份是覆盖" |

**建议**：等 `librime-next` 的 config 层稳定后**一次性统一**（它本来就是 YAML），不要分两次迁。

## 二、YAML 的键能不能用中文

**能。** YAML 的键是任意 UTF-8 标量；yaml-cpp 与 `serde_yaml` 都支持。
rime 自己的 `symbols.yaml` 里整张 punctuator 表就是用中文标点当键的（`'，' : ，`）。

### 四条边界（踩了会静默读不到）

| 边界 | 原因 |
|---|---|
| **librime 代码里按名字读的键必须 ASCII** | `schema/schema_id`、`speller/algebra`、`engine/processors`、`punctuator/import_preset` 都是字符串字面量 |
| 键里不能有 `/` | rime 路径语法 `a/b/c` |
| 键里不能有 `:` | YAML 需引号；`file:/path` 引用会歧义 |
| 不要 `__` 开头 | 指令命名空间：`__include` / `__patch` / `__build_info` |

### 建议的分层

```yaml
# 用户层：中文键（我们自己定）
双拼:
  scheme: 小鹤
中英切换:
  未确认编码: 上屏        # inline_ascii | commit_code | commit_text
音效:
  模式: 打字演奏
  音量: 0.55
```

```yaml
# librime 层：ASCII 键（改不得，生成时由我们翻译过去）
schema:
  schema_id: double_pinyin_ziranma
speller:
  algebra: [...]
```

## 三、i18n 现状：完全没做

```
Setting/ui/*.slint   @tr( 命中 0       中文文案 150 条
stats 44 / main 27 / wasm-modules 21 / color-editor 18 / app-options 9 / dicts 9 / schemas 8 / progress 8 / color-schemes 6
Server/src/notifications.rs          35 行含中文（弹窗）
Engine/src/engine.rs                357 行含中文（诊断日志，不必翻）
installer/*.nsi                      MUI2 自带多语言，改 MUI_LANGUAGE 即可
```

### 三条路

| 路 | 做法 | 代价 | 适合 |
|---|---|---|---|
| **A** | Slint 官方 `@tr()` + `.po` + `include_translations!` | 中（改 150 处 + 构建接线） | 长期标准做法 |
| **B** | 自建字符串表 `t(key)`，Slint 用 `in` 属性注入 | 中（不引依赖、不用 po 工具链） | 不想加构建复杂度 |
| **C** | 只做外壳：托盘菜单 + 弹窗 + 安装器 + 方案名显示 | **小（约 50 处）** | 先看效果 |

**建议 C → A**：先做用户第一眼看到的部分，再把设置界面那 150 条迁到 `@tr()`。

### 必须先定的三点

1. **语言从哪来**：推荐配置项 `language: zh-CN`（与中文键配置天然一致），而不是靠 `LANG`。
2. **中文键 ≠ 配置 i18n**：i18n 只在**界面**层；配置键**永远一套固定名字**。
   否则键名变动态，可读性和可维护性全毁。
3. **`schema/name` 只有一份**：librime 不支持多语言方案名。
   要 i18n 只能在**显示时查表**（`double_pinyin_ziranma` → `自然码双拼` / `Ziranma`），不能改文件。

### 工作量

- C：约 **1 天**（`language` 配置项 + 两张表 + 托盘/弹窗/安装器）
- A：约 **2–3 天**（150 处 `@tr` + po + 构建接线 + 只留 zh/en）
