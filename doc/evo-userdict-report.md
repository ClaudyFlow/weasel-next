# evo 用户词库 · 技术速览

> 一句话：把 librime-evo 的**用户词库格式与三模式学习**移植进 Rust 引擎（librime-next），
> 在 LevelDB 里用**五字段值**存词，支持**自动学习 / 只手排 / 关闭**三档，并保留旧库兼容。

---

## 1. 它解决什么问题

上游 librime 的用户词库只有三个字段：`c`（选词次数）、`d`（衰减词频）、`t`（时间戳）。
这带来两个硬限制：

1. **没有"用户手排"的位置**——用户没法把某个候选钉死在第几位；
2. **模式只有开关两档**——要么全自动学，要么整个关掉。

evo 的改法是**向后兼容地加两个字段**，不换格式、不迁移老库。

---

## 2. 数据格式：五字段

磁盘上的 value（LevelDB，一条一个词）：

```
21,3.50902,3402,2,6fn3k
```

| 字段 | 名字 | 含义 |
|---|---|---|
| `c` | commits | 累计选词次数；**负数 = 已被用户删除**（读到负值直接丢弃） |
| `d` | dee | 衰减后的词频权重，上限 10000；衰减公式 `d + da·e^{(ta−t)/200}` |
| `t` | tick | 最后一次改动的 tick（算衰减量用） |
| `p` | position | **手排位置**（1 基；0 = 自动排序） |
| `m` | manual_stamp | 手排名次戳：两处手排冲突时"新的覆盖旧的" |

**兼容性**：旧格式 `c=21 d=3.50902 t=3402` 照样能读（缺的两位按 0）；
新库被旧版读也只是丢掉手排信息。所以**不需要数据迁移脚本**。

### `m` 为什么是短码

64 位十进制时间戳要占 10–12 字节/条，十万条就是 1.5 MB 纯噪声。
evo 的做法：**以 2026-01-01 为纪元、转 36 进制**——5–6 个字符（`6fn3k`），体积减半。

```
0                      → "0"       （未手排）
1767225600 (2026-01-01) → "1"
1798761600 (2027-01-01) → "6fn3k"
```
"早于纪元"的时间统一压成 1（0 留给"没手排"），保证系统时钟被拨回也不会让手排凭空消失。

## 3. 三模式

```yaml
translator:
  user_dict_mode: auto     # auto（默认）| manual | off
```

| 模式 | 自动学习 | 自动删除 | 手排 | 建库 |
|---|---|---|---|---|
| `auto` | ✅ | ✅ | ✅ | ✅ |
| `manual` | ❌ | ❌ | ✅ | ✅ |
| `off` | ❌ | ❌ | ❌ | ❌（组件不创建） |

配置走 `<namespace>/user_dict_mode`，非法值会打日志并禁用该词典（不静默）。
`off` 与上游的 `enable_user_dict: false` 等价，只是写法更明确。

---

## 4. 手排机制

- `set_manual_position(entry, pos)`：把词固定到第 `pos` 位（0 = 取消）；
- `move_manual_one_step(...)`：与邻居交换；邻居不可见时不动（避免挤掉隐藏词）；
- `reset_manual_position` / `reset_auto`：分别清手排 / 清自动排序（`reset_auto` 保留手排钉住的位置）；
- 冲突判定：**`m` 大的赢**——两处手排同一个词时，新的覆盖旧的。

手排**不受模式限制**：`manual` 模式存在的意义正是"只有手排生效"。

---

## 5. 存储与命名

- 引擎：LevelDB（每本词典一个目录）；
- 路径：`%APPDATA%\Rime-Next\userdb\<库名>.userdb`；
- 库名：方案 `translator/dict:` 的第一段（`pinyin.luna` / `pinyin.terra` / `double_pinyin.ziranma` 共用 `pinyin.userdb`），
  也可用 `translator/user_dict:` 显式覆盖；
- 前缀关掉（`enable_user_dict: false` 或 `db_class` 不是 `userdb`）就**不建库**。

## 7. 边界与未完成（诚实版）

1. **手排没有宿主入口**：`set_manual_position` / `move_manual_one_step` / `reset_manual_position`
   在整个仓库**零调用者**——C API 没导出、Engine/Tip/Setting 没接。
   所以 `p`/`m` 现在恒为 0，`manual` 模式即使打开也没有东西会调它。
2. **老条目仍是三字段**：读兼容，写新的；不会自动重写。
3. **092 方案 `enable_user_dict: false`**：那套方案一个字都不学。
4. 用户词库**按实际词库（dict）命名**，不是按方案 id——同族拼音方案共享学习记录。

## 8. 一页数字

| 指标 | 值 |
|---|---|
| 每词存储 | 约 20–25 B（五字段文本 + LevelDB 开销） |
| 手排戳 | 5–6 字符（36 进制），比十进制省一半以上 |
| 词频衰减半衰式 | `d(t) = d + da·e^{(ta−t)/200}`（tick 单位） |
| 单测 | 24（学习/格式）+ 14（手排）= 38 条 |
